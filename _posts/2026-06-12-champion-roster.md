プレイアブルキャラクターを6体、LoL のアーキタイプを参考に設計した。同時に「バランス調整のたびにエディタでアセットをポチポチ直す」未来を回避するため、**パラメータを JSON に一元化**した。

## ロースター

| キャラ | ロール | LoL参考 | 設計の軸 |
|---|---|---|---|
| ゼフ | メイジ | ルブラン/アーリ | 基準キャラ。HP200・射程12のバランス型 |
| ガロン | タンク | ガレン/ダリウス | HP320・近接・鈍足。R は至近の処刑技 |
| ヴェイル | アサシン | ゼド/カタリナ | HP180・最速6.0。R 威力160で単体最大火力 |
| リン | マークスマン | ケイトリン/ジンクス | AA射程15・Q射程22。全てが長い |
| ノヴァ | サポート | ラックス/オリアナ | 半径4.5の広域AoEで面制圧 |
| ソーン | ジャングラー | ヴァイ/ワーウィック | 新規。準タンク+高機動のダイバー |

スキル構成は全員 Q=方向指定 / E=地点AoE / R=対象指定 に統一し、**差別化は数値で行う**(射程・CD・半径・威力)。操作の学習コストを一定に保ったまま、リンの Q22 とガロンの Q6 のような「同じ操作、違う間合い」が生まれる。近接キャラの R は射程が短い代わりに威力を高くしてリスクリターンを付けた。

## JSON が正、アセットは成果物

データフローはこう:

```
characters.json(人間が編集)
  → Enigma/Import Character Roster(メニュー1クリック)
  → CharacterData / SkillDefinition アセット群を上書き生成
```

肝は **GUID 維持**。既存アセットを「削除して作り直す」のではなく「ロードして上書き」するので、シーンやデータベースからの参照が壊れない(プレハブ再生成で Rigidbody が消えた事件の教訓が生きている)。パースとバリデーションは Unity 非依存の plain C# で、「id 重複」「targeting の綴りミス」のような事故は具体的なエラーメッセージで弾く(テスト19件)。

ステータスは試合開始時に反映される: HP320 のガロンを選べば最大HPが実際に320になり、AAの射程・威力・速度も移動速度もキャラごとに変わる。**数値をいじって再インポートするだけでバランスパッチが完成**する。

## モデルは CC0、ピックで差し替わる

Quaternius の「LowPoly RPG Characters」(CC0、リグ+アニメ付き)から騎士・盗賊・狩人・僧侶・格闘士の5体を導入。ピック画面で選んだキャラのモデルが試合開始時にランタイムで差し替わる(高さ正規化→接地→トゥーン化→攻撃モーションの参照差し替え)。移動速度に応じて Idle/Walk アニメも自動で切り替わる。ゼフだけはこのゲームの顔なのでユニティちゃんを継続。

ハマりどころをひとつ: FBX をリネームしたら**ファイル内部のテクスチャ参照が切れて全員真っ白**になった。FBX は元のテクスチャファイル名を覚えているので、リネーム運用するなら命名規約でテクスチャを明示的に再結線する仕組みが要る。

数字で見るこのラウンド: 6キャラ×3スキル=18スキル定義、EditMode テスト 232→250件。
