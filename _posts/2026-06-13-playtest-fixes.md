フレンドリーファイア、ボットの突進、そして「どう見ても押せるはずのボタン」が押せない謎。今回のプレイテストフィードバック対応ラウンドで潰した問題を記録しておく。

## フレンドリーファイア無効化 — TeamRules を単一ソースに

チームメイトへの誤射問題は「判定を一か所に集中させる」方針で解決した。`TeamRules` という plain C# クラスを用意し、「同チームか」を判断するロジックを全ファイルから引っ張るようにした。

弾の挙動については「味方に命中したら消す」ではなく**素通り**にしている。消えると弾が味方の背後から飛んでいる様子が見えて射線が塞がる感覚を与えるためだ。味方オブジェクトをクリックしてもターゲット選択が発生しないようにも合わせて修正した。

## ボットが壁に頭突きし続ける — 法線スライド操舵

ボットがタワーや壁に対して正面から突っ込み、そのまま前進し続けるケースがあった。

修正はシンプルな球体キャスト:前方 2.5m に対して `SphereCast` を飛ばし、ヒットがあった場合はヒット面の法線に沿って操舵ベクトルをスライドさせる。壁際でも速度を大きく落とさず滑らかに迂回できるようになった。

## AA 射程リング — Alt キーへ変更

「長押しで AA 射程を表示するリングが欲しい」という要望を実装したところ、最初に **A キー**に割り当てて大失敗した。WASD 移動の A(左移動)と完全に衝突し、歩いた瞬間にリングが出る。即 **Alt キー長押し**に変更して解決。キー割り当ては必ず移動系と突き合わせてから決めるべきという当たり前の教訓。

## 探偵もの: 「スキルのレベルが上げられない」

ここからが今回のメインだ。

プレイテスト参加者から「スキルの + ボタンを押してもレベルが上がらない」という報告が来た。

### 疑いリストを潰す

まず疑うべきところを順番に確認した。

- **ポイント付与ロジック**: レベルアップ時にスキルポイントが正しくインクリメントされている ✓
- **ランクアップ処理**: `SkillRankUp()` メソッドは条件チェックを通過してランクを上げられる状態 ✓
- **UI のヒットテスト** (`panel.Pick`): ボタン位置の座標で `Pick` を呼ぶと `Button` 要素が返ってくる ✓
- **クリックイベントリスナー**: 登録済み ✓

全部正常。なのにプレイヤーは押せない。

### 実マウスで観測する

合成イベントで「届いている」と判定していたのが盲点かもしれない。ここで **computer-use(AI がマウスを実際に動かすツール)** を使い、本物のクリックをボタン座標に送った。

UI ルートに `PointerDown` を観測するプローブを仕込んでおき、クリック後にイベントが届いたか確認する。

結果: **パネルに `PointerDown` イベントが一度も届いていない。**

クリック自体は発火しているが、UI Toolkit のルートパネルにすら到達していなかった。

### 真因: はみ出したボタン

`+` ボタンの USS を確認する。

```css
/* スキルスロットの + ボタン */
.skill-rank-up-btn {
    top: -19px;
    width: 20px;
    height: 16px;
}
```

**`top: -19px`。** ボタンが親パネルの上端から 19px 上方にはみ出している。

UI Toolkit では、要素が親パネルの境界外に出た部分は**クリック不能**になる。20×16px のボタンのうち実際に押せる領域は境界内に残った下側数 px だけだった。`panel.Pick` が「通る」のは、Pick が UI ツリーのヒットテストを返すためで、**OS レベルのウィンドウ領域外クリックとは別の話**だ。

「Pick は通るのに実クリックは死んでいる」という症状が成立する理由がここにある。

### 修正

ボタンをスロット上端の内側に収め、スロット全幅にわたるストリップ状に変更した。クリック可能面積は修正前比で 3 倍以上になった。

実マウスで「クリック → ランクアップ → ポイント消費」の全連鎖を確認して完了。

## 教訓

- **UI の最終検証は合成イベントではなく実入力で行う。** `panel.Pick` や `SendEvent` は「UI ツリー上の到達性」しか保証しない。はみ出し・overflow:hidden・別ウィンドウへの遮蔽など、実クリックが死ぬ経路は複数ある
- **ボタンが「見えている」と「押せる」は別の概念。** CSS の負オフセットは視覚的には正常に見えるが、クリック領域は親境界に縛られる
- **computer-use は最後の観測手段として有効。** 合成イベントでは再現しないバグを、実マウス入力で一発で再現させられた

数字で見るこのラウンド: 変更 18 ファイル、新規テスト 4 件追加、スキルスロット CSS 修正 1 箇所。
