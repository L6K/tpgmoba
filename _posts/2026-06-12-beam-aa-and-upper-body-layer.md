「弾が飛ぶだけのAA」から「手元から放たれるビーム」へ。今回のラウンドはアニメーションの深い部分に踏み込んだ。

## まず足場: NPCの歩行モーション

ビーム実装の前に、ずっと気になっていた問題を片付けた。**敵NPCが足音もなく滑りながら移動していた**のだ。移動処理はNavMeshで正しく動いているのに、Animatorが Idle クリップを流し続けていたのが原因。

Playables API で **Idle / Walk の2クリップをクロスフェード切替**するだけで解決した。AnimationMixerPlayable に2つのクリップを食わせ、移動速度が閾値を超えたら Walk にウェイト1.0を渡す。Animator Controller を一切使わず、コードだけで完結する。

これだけで「浮き上がって移動する人形」が「地面を歩いているキャラクター」に見えるようになった。足がついただけで視覚的な説得力が別物になる。

## AAをビーム化: マズルの付け替え

通常攻撃のプロジェクタイルはこれまで空中の固定点から発射していた。これを**右手ボーン(Character1_RightHand)の子オブジェクトとしてマズルを配置**し、手元から飛び出すビームに変更した。LoLのエズリアルがポータルから腕を突き出してビームを撃つ、あの見た目に近い。

ビーム自体は LineRenderer で済む。マズル位置を始点、ヒット位置(またはレイの最大到達点)を終点にセットするだけ。弾速という概念がなくなり、「ボタンを押した瞬間にビームが届く」快速感が出た。

## 問題発覚: 攻撃クリップで足がガタつく

喜んで攻撃させてみたところ、AAのたびに**足がガクガクと揺れる**のに気づいた。攻撃アニメーション(HANDUP00_R)が**全身アニメーション**として作られているため、上半身が上がるフレームで下半身も引きずられてしまうのだ。

NavMeshで歩かせながらAAを撃つと、足の位置が攻撃クリップに引っ張られてワープする。見栄えが最悪になった。

## 解決策: AnimationLayerMixerPlayable + AvatarMask

Animator Controller の「レイヤー + AvatarMask」機能は有名だが、Playables API でも同等のことができる。**AnimationLayerMixerPlayable** がそれだ。

構成は2レイヤー:

| レイヤー | クリップ | AvatarMask |
|---|---|---|
| 0(ベース) | Idle / Walk | なし(全身) |
| 1(上半身) | HANDUP00_R | 上半身のみ |

`AddLayerMixerPlayable` でミキサーを作り、レイヤー1に `SetLayerAdditive(1, false)` と `SetLayerMaskFromAvatarMask(1, upperBodyMask)` を設定する。攻撃開始でレイヤー1のウェイトを1.0に、終了で0.0に戻すだけ。

## 数値で証明する: 足は動かず、腕だけ動く

「本当に足が止まっているか」を定量的に確かめたかったので、攻撃クリップ再生中(90フレーム)に各ボーンの変位を記録した。

| ボーン | 変位 |
|---|---|
| 左足(LeftFoot) | **0.000 m** |
| 右足(RightFoot) | **0.000 m** |
| 右手(RightHand) | **0.79 m** |

足ボーンの変位がきっかり0.000。上半身マスクが下半身ボーンに一切干渉していないことを数値で確認できた。腕は0.79mを大きく動いており、攻撃モーションが正しく乗っている。

## 教訓: Mecanim なしでも레이어合成は素直に組める

今回の一番の収穫は「**Animator Controller を使わなくても、Playables API + AvatarMask でレイヤー合成が完結する**」という実感だ。

Animator Controller はビジュアルグラフが親切な反面、「コードから制御したいのにグラフにも状態が散らばる」という二重管理の悩みが生まれる。このプロジェクトではロジックをコードに集約する方針なので、Playables API で全部書いた方が見通しがよい。AnimationLayerMixerPlayable はドキュメントが少なく最初は手探りだったが、仕組みはシンプルだった。

足を止めたまま腕だけを振り回すキャラクターが、ようやく完成した。
