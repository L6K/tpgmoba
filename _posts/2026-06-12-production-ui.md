## デザイン言語を一つに決める

バラバラに作った UI は「安っぽさ」に直結する。今回まず最初にやったのは、配色・フォント・装飾ルールの言語化:

- **パレット**: 深紺 `#0A0E1A` / 金縁 `#C8AA6E`(暗部 `#785A28`) / 羊皮紙テキスト `#F0E6D2`
- **フォント**: 英数字は Marcellus(LoL の Trajan に近い石碑風セリフ)、和文は Noto Sans JP — どちらも OFL の無料フォント
- **装飾**: 角丸は 2〜3px に抑え、強調は「金のライン」で行う

この言語を HUD・ミニマップ・開発ログサイト(本サイト)まで一貫させている。

## ミニマップは「描く」のではなく「ベイクする」

以前のミニマップは色付きドットを並べただけの簡易版だった。今回は**実際のマップを正射影カメラで真上から撮影してテクスチャ化**する方式に変更。エディタスクリプトがシーンを開いた状態で 1024px の PNG を書き出し、UI はそれを円形フレームで表示するだけ。

この方式の利点:

- マップの地形を変えても**ベイクし直せば常に正確**(手描きミニマップの宿命である「実際と違う」が起きない)
- 実行時コストはゼロ(静的テクスチャ+動くアイコンのみ)
- レーンや川の形がそのまま伝わる

その上に、プレイヤー=向き連動の矢印、タワー=菱形、中立=紫、ミニオン=小ドットのアイコンレイヤーを重ねる。

## こだわり: 目盛りルールを plain C# で共通化

HP バーの目盛り(LoL の 100HP 刻みのアレ)は、ワールド空間の頭上バーと HUD の UI Toolkit バーの**両方**に必要だった。描画系が全く違う2箇所に同じルールを実装すると必ずズレるので、ルールだけを純粋関数に切り出した:

```csharp
public static float TickUnit(float maxHp)
{
    if (maxHp <= 500f)  return 50f;
    if (maxHp <= 2000f) return 100f;
    return 500f;
}
```

ワールド側は Quad の位置、HUD 側は `left: %` に変換するだけ。境界値(500/2000、倍数/非倍数)は EditMode テストで固定してある。

## バグ解剖: 「攻撃してもダメージが入らない」

今回最大の収穫はこれ。プレイテストで「ミニオンを殴っても HP が減らない」という報告があり、調査すると**奇妙な非対称**があった: 敵の弾はプレイヤーに当たる(被弾の赤い数字は出る)のに、こちらの弾だけ誰にも当たらない。

原因は Unity の物理の基本ルールだった:

> **トリガーイベントは、ペアのどちらかに Rigidbody がないと発火しない。**

弾はトリガーコライダーのみで Rigidbody を持っておらず、ミニオンも素の CapsuleCollider だけ。つまり**静的コライダー同士のペア**になり、`OnTriggerEnter` は一度も呼ばれていなかった。プレイヤーにだけ当たっていたのは、`CharacterController` がキネマティック Rigidbody 相当として振る舞うため。

```csharp
// 弾側にキネマティック Rigidbody を1つ持たせるだけで全ペアが復旧する
var projRb = projGo.AddComponent<Rigidbody>();
projRb.isKinematic = true;
projRb.useGravity  = false;
```

さらに闇が深いのは「**昔は倒せていた**」こと。旧ミニオンプレハブには Rigidbody が残っており、別の不具合対策で「プレハブを毎回ゼロから再生成する」方式に変えた際、誰も意識しないまま Rigidbody が消えていた。コンポーネント構成が暗黙に変わる系のリグレッションは本当に気づきにくい。

## TIPS(今回踏んだ落とし穴)

- **UI Toolkit の `flex-grow: 1` は column コンテナ内では縦に伸びる**。横バーのつもりの要素が高さ28pxの謎の帯になった。行(row)から列(column)へ要素を移動した時は flex 指定を見直すこと
- **エディタが非フォーカスだと USS/UXML の変更が自動インポートされない**。コードから `AssetDatabase.ImportAsset(..., ForceUpdate)` を呼ぶか、エディタにフォーカスを渡す
- **`ScreenCapture.CaptureScreenshot` は Game ビューの論理解像度で撮れる**。UI のスケーリング検証は Game ビューを 1920x1080 固定にしてから撮らないと、PanelSettings の縮小で「UIが小さすぎる」と誤診する(実際に誤診しかけた)
- **UXML の名前空間プレフィックスを宣言し忘れると「空アセット」として静かにインポートされる**。エラーが出ないので気づきにくい。一度壊れた UXML は修正後に ForceUpdate での再インポートが必要

## 残っている課題

- スキルアイコンが Targeting 種別ベースの汎用アイコン(CC0 の Kenney Game Icons)で、スキル個別の絵柄ではない
- ミニマップの金縁が細く、視認性がもう一歩
- ダメージ数字のフォントが TextMesh のデフォルトのまま(HUD と統一したい)
- CD 中のスキルスロットのワイプ演出は入ったが、使用可能になった瞬間の「光る」演出がない
