# データ設計

## 方針

ローカル保存に SQLite を使用する。DB管理ツールとして A5:SQL Mk-2 を使用する。

| 要素 | 内容 |
|---|---|
| **DB本体** | SQLite（ローカルファイル） |
| **Unityライブラリ** | SQLite-net（NuGetForUnity経由） |
| **管理ツール** | A5:SQL Mk-2（開発中のデータ確認・編集用） |
| **保存場所** | `Application.persistentDataPath/enigma.db` |

> サーバーサイドを実装する場合は SQL Server / PostgreSQL を別途検討する。

## テーブル設計

### player（プレイヤー情報）

| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | プレイヤーID |
| name | TEXT | プレイヤー名 |
| currency | INTEGER | 所持通貨（ガチャ用） |
| created_at | TEXT | 作成日時 |

### owned_chars（所持キャラクター）

| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | レコードID |
| player_id | INTEGER FK | プレイヤーID |
| char_id | TEXT | キャラクターID |
| acquired_at | TEXT | 取得日時 |

### owned_skins（所持スキン）

| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | レコードID |
| player_id | INTEGER FK | プレイヤーID |
| skin_id | TEXT | スキンID |
| acquired_at | TEXT | 取得日時 |

### match_history（マッチ履歴）

| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | マッチID |
| player_id | INTEGER FK | プレイヤーID |
| result | TEXT | 勝敗（WIN / LOSE） |
| kills | INTEGER | キル数 |
| deaths | INTEGER | デス数 |
| assists | INTEGER | アシスト数 |
| damage | INTEGER | 与ダメージ |
| played_at | TEXT | 試合日時 |

### gacha_log（ガチャ履歴）

| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | レコードID |
| player_id | INTEGER FK | プレイヤーID |
| item_id | TEXT | 獲得アイテムID |
| item_type | TEXT | 種別（char / skin） |
| pulled_at | TEXT | ガチャ実施日時 |

---

## 名前空間

`Enigma.Data` でDB操作を一元管理する。

```
Enigma.Data
  ├── DatabaseManager.cs   // DB接続・初期化
  ├── PlayerRepository.cs  // playerテーブルのCRUD
  ├── MatchRepository.cs   // match_historyのCRUD
  └── GachaRepository.cs   // gacha_log / owned_chars のCRUD
```
