# アーキテクチャ

## レイヤー構造

```
┌─────────────────────────────────┐
│          Presentation           │  UIManager, HUD, ミニマップ
├─────────────────────────────────┤
│           Game Logic            │  キャラ・スキル・戦闘・ミニオン・オブジェクト
├─────────────────────────────────┤
│         Infrastructure          │  EventBus, GameManager, NetworkManager
├─────────────────────────────────┤
│             Data                │  ScriptableObject（キャラ定義・スキル定義）
└─────────────────────────────────┘
```

| 名前空間 | 役割 |
|---|---|
| `Enigma.Core` | GameManager・EventBus・定数。試合の状態管理（開始・終了・降参） |

| `Enigma.Ability` | スキル定義（ScriptableObject）＋実行（MonoBehaviour） |
| `Enigma.Combat` | ダメージ計算・CC管理・デス/リスポーン |
| `Enigma.Objective` | タワー・タイタンのHP管理 |
| `Enigma.Minion` | ウェーブスポーン・NavMesh AI |

| `Enigma.Minimap` | ワールド座標→ミニマップ変換 |
| `Enigma.UI` | 画面遷移・HUD更新 |

## 設計方針

### EventBus で疎結合
システム間の直接参照を避け、EventBus 経由でイベントを通知する。

```
例: キャラクター死亡
OnCharacterDied イベント発火
  ├── UIManager    → デス画面表示
  ├── CombatSystem → リスポーンタイマー開始
  └── MinionSystem → キル数カウント更新
```

### ScriptableObject でデータ定義
キャラのステータス・スキル効果はコードでなく ScriptableObject で管理する。
コードを触らずにバランス調整が可能。

### NetworkBehaviour は薄く保つ
ネットワーク同期は最小限に絞る。

| 同期対象 | 方式 |
|---|---|
| 位置・回転 | NetworkTransform |
| HP / MP | NetworkVariable |
| スキル発動 | ServerRpc / ClientRpc |
| ミニオン状態 | NetworkVariable |

ゲームロジックはサーバー権威で処理し、クライアント側は予測移動のみ行う。
